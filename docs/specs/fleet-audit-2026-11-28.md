## Appendix — method

Each check and how it is probed (all read-only):

- **Topic** — `gh repo view --json repositoryTopics`; opt-in requires the repo be listed here AND carry `shepherd-managed` (DESIGN §2).
- **Config / Dependabot / Makefile / Caller / Gates** — `gh api repos/<r>/contents/<path>?ref=<default>`.
- **Secret** — `gh secret list`; needs admin on the repo, else ❔.
- **dry_run** — `dry_run: true` in `.shepherd.yml` ⇒ ⚠️ (reporting-only).
- **Pin** — `reusable-shepherd.yml@<sha>` in the caller; compared to the newest local shepherd tag (v0.10.2-rc1). Mutable (non-40-hex) ref ⇒ ❌; behind-latest ⇒ ⚠️.
- **default=dev / dev+main** — `gh repo view --json defaultBranchRef` + `gh api .../branches/{dev,main}`.
- **9 targets** — Makefile (+ `mk/ci.mk` when included) exposes build, test, test-affected, smoke, release-artifacts, ci-branch, ci-patch, ci-release, ci-nightly.
- **schema v1** — `.shepherd.yml` has version, risk, build, test, auto_merge.
- **ci-tiered** — ci-branch.yml + ci-patch.yml + ci-release.yml present.
- **SHA-pin** — every `uses:` in `.github/workflows/*` is a 40-hex SHA or a local `./` ref. Composite actions under `.github/actions/**` are NOT deep-scanned here — `shepherd-bump --verify-sha-pin` is the authoritative check.
- **pre-push** — a `make check` pre-push hook via `.pre-commit-config.yaml`, `.husky/pre-push`, or `.githooks/pre-push`.
- **test-affected** — the Makefile recipe is diff-aware (script / changed-file selection) vs an identity alias (⚠️, contract-permitted when a repo has no module graph).
- **Pipeline health** — `gh run list --workflow <wf> -L 1` conclusion.

Overlap: Dependabot / shepherd caller / gates caller appear in both the arming
and best-practice matrices by design — the two matrices are distinct lenses
(is-it-armed vs does-it-follow-the-contract) folded from the two precursor audits.

**Not inspected:** managed repos' own non-shepherd CI (e.g. a repo's `ci-nightly`
failing for its own reasons) is reported under pipeline health but triaging it
belongs to that repo's owner / the SH-020 digest.
