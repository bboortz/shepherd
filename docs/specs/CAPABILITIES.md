# Capabilities — shepherd

The source of truth for what Shepherd does. Every capability is a mechanical property we can test. Entries are seeded from `docs/specs/DESIGN.md §12`; they become test-linked once the Action lands in Release 1.

Each row: a stable `cap.id`, a one-line description, the source paragraph in DESIGN.md, and — once tests exist — a bidirectional pointer to the acceptance test that proves it. `make verify-traceability` will enforce bidirectional links from R1 onward.

Status values: `design` (described in DESIGN, not implemented yet), `active` (implemented, test-linked), `aspirational` (R2+), `deprecated`.

## Dev cycle (SH-014 umbrella)

One pipeline model across the fleet. Eight `make` targets exposed by every managed repo; tier budgets 5/5/15/∞ enforced by workflow `timeout-minutes`. Each CAP ships with a sub-story; `design` status until the sub-story lands.

The three agent entry points (`test-affected`, `smoke`, `release-artifacts`) carry the build-once-promote mechanic; each repo aliases to its native idiom (homelab `test-updates`, forge `smart-check.sh`, etc.) or inherits the identity default. | SH-014 + SH-016 + `docs/specs/dev-cycle-contract.md` | design | — (R2 scope — `test/acceptance/test_SH_016_*.sh` when SH-016 lands) |
